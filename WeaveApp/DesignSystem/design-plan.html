design-system branchPlan v2: based on your references

Weave,
bolder.

The new direction takes four things from your references: heavy display type, big rounded tiles laid out in a grid, solid pastel color blocks, and dark mode as the main mode. Weave's deep green stays as the brand color.

Each component below appears twice, light and dark, the same way each SwiftUI #Preview will.

What I took from each reference

I kept the look and left out the game mechanics. Weave asks friends to cover each other's time, so ranking them against each other would work against the product.

Account / bonuses

Heavy black type, a big number with a small label under it ("1926 / bonuses"), white tiles next to one deep-green tile. This becomes the BalanceCard.

Mood picker

Overlapping colored cards with a round button on each. This becomes PrivacyChoice, with Keep Private as the card on top.

Dark bento grids

Near-black background, charcoal tiles, tight gaps, small pill tags ("15 min", "Evening"). These set the dark-mode tokens and WeaveChip.

Podcast insights

A grey sentence with bold white numbers, and a capsule button. This sets the Secondary button and the type contrast.

Top Artists story

A bold editorial feel with yellow accents. Yellow becomes the caution color.

Leaderboard / lessons

Saturated stacked cards and white and black capsule buttons. This sets the Primary button. Coral becomes the critical color.

Left out on purpose

Points, crowns, ranks, streak flames, badge collections. Those make it a contest, which goes against Weave's calm and private-by-default tone.

Feed cards get a color from the member's name, using a stable hash. Alice is always peach and Bob is always pink, on every device and in every Kane screenshot.

Typography

SF Pro in heavy weights with tight letter spacing. No custom font file, so the Xcode project needs no resource changes. Every style is tied to a Dynamic Type text style, so it still scales with the user's text-size setting.

Components

Every user-visible string is still a parameter, and each Kane-checked string still renders as one text element. Components take an optional accessibilityIdentifier so IDs like group.balance keep working.

Capsule buttons like in your references. Primary is solid ink (black in light mode, white in dark), with an optional round arrow at the end. Secondary is a quiet grey capsule. Both are 58pt tall. Privacy choice

PrivacyChoice

Two overlapping cards, based on the mood picker. Keep Private is the mint card on top: it has a shadow, a filled check and a black "Default" chip, and it's selected when the screen opens. Share with Group sits behind it in periwinkle and comes forward when tapped. Each card is a full-size tap target (well over 44pt), and VoiceOver reads them as a two-option radio group.

How I'll build it

  • One text element per Kane string. For BalanceCard, "40 credits" is passed as one string. The component splits it only for display, joining two Text views with +, so VoiceOver and Kane still read exactly "40 credits".
  • Colors in code. Each token is a Color built from a UIColor that changes with light and dark mode. No asset catalog and no custom fonts, so the Xcode project gets no resource entries.
  • No hard-coded user text. Titles, badges, chips, summaries and tags are all parameters. Avatar initials and pastel colors are computed from memberName.
  • Previews. Each component file gets #Preview("Light") and #Preview("Dark") with Alice, Bob and Charlie, 40 → 30 credits, and "10 minutes · 10 credits".
  • Accessibility. Dynamic Type on every style, each card read as one VoiceOver element, PrivacyChoice as a radio group, tap targets of at least 44pt, and Reduce Motion respected for the card animation.
  • Existing WeaveStyle stays as it is. It's in WeaveApp.swift, which is out of scope. The feature screens can move to WeaveTheme later.
  • Build check only: xcodebuild -scheme Weave -sdk iphonesimulator -configuration Debug -derivedDataPath build-design build. No Kane runs, no simulator, no Scripts/.
